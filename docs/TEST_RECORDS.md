### 2026-09-20 M7：SSE 实时推送 + 人工会话导入
- **SSE 实时推送**（替代前端轮询为主）：后端 `/api/events` 事件流（线程安全队列 + asyncio 桥接，15s 心跳），任务运行状态（running/retrying/succeeded/failed）即时广播
  - 冒烟：订阅期间触发任务 #4 → 收到 `running` + `succeeded` 两条事件 ✅
  - 浏览器验收：任务详情页不点刷新，新运行记录约 2s 自动出现"运行中"、7s 后自动变"成功" ✅；任务列表页 EventSource 连接活跃 ✅；顺带修复触发方式列 Webhook 紫色标签渲染
- **人工会话导入**（验证码类系统的插件辅助先行版）：`PUT /api/systems/{id}/session` 粘贴 Playwright storage_state JSON → 写入 `sessions/system_<id>.json`，解析/任务运行免登录直达
  - 冒烟（最严场景）：**错误密码 + 清空会话文件** → API 导入正确会话 → 解析 succeeded（profile #11）——证明解析走的是导入会话而非自动登录 ✅
  - 浏览器验收：Systems 页「导入会话」按钮 + Modal + 坏载荷红字报错 + 合法 storage_state 绿字成功 ✅
- 踩坑：SPA 页面切换时旧 SSE 连接被浏览器主动 abort（ERR_ABORTED）属正常现象，非缺陷

### 2026-09-20 两步式门户登录（引擎能力）
- 场景：企业统一门户页（点击「进入系统」后才出现登录表单，Dolibarr 型）
- demo-target 新增 `/portal` 门户演示页；系统配置 `pre_clicks=["text=进入系统"]`
- 结果：✅ 登录 + 解析（8 字段/3 动作）+ 建任务运行全链路通过
- 过程修复：登录成功判定原以配置的入口 URL 为基准，门户场景会在提交后立即误判"已离开"导致登录被打断——改为以「提交时刻 URL + 用户名框消失」判定
